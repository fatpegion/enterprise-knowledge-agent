# 需求

员工需要找到能回查的制度或产品答案。例如接待员工要查访客网络接入，报销员工要确认票据时限，使用基础版的员工要确认可导出的最高规格。

输入为 JSON 对象。必填 `question`，可选 `history` 数组，最多 8 条 user 或 assistant 消息。资料采用合成 FAQ 和制度，每份文档具备文档 ID、版本日期和片段 ID。

| 场景 | 成功标准 |
| --- | --- |
| 明确答案 | 回答访客接入步骤，逐字引用 D03 原文 |
| 文档冲突 | 读取 D01、D02，补查适用范围或优先级；无法消歧时列出 30 天和 15 天，请用户确认制度 |
| 资料外问题 | 补搜后仍无证据，说明覆盖缺口，不作事实答复 |
| 改写后的相似问题 | 「来客上网」也能定位 D03，引用支持答案的原文 |
| 上下文追问 | 根据历史锁定基础版和视频导出，使用 D04 回答 1080p |
| 工具失败 | 将失败观察返回给模型；必要证据无法获取时返回明确状态和缺口 |

输出含 `status`、`answer`、`citations`、`evidence_gap`、`backend` 和 `trace`。CLI 是本项目交付入口。范围聚焦小型静态资料库、可追溯答复和单次问答，历史由调用方传入。
